## Context

项目当前只有 OpenSpec 配置，需要从零建立一个可安装、可测试的 Tampermonkey 用户脚本。脚本运行在 `https://www.guangyapan.com/*`，需要跨域访问 TMDB，同时复用光鸭网页现有登录态调用云盘 API。

通过真实页面已验证：

- 目录列表请求为 `POST https://api.guangyapan.com/userres/v1/file/get_file_list`。
- 文件重命名请求为 `POST https://api.guangyapan.com/userres/v1/file/rename`。
- 请求使用 Bearer 授权与设备上下文，脚本不得把这些凭据写入源码。
- 当前真实样本同时包含日期、混合分隔符和“第 10 期上/中/下”，不能用单一完整文件名正则解决。

TMDB API 能通过 TV Search 确定 series id，再通过 Season Details 返回正季或 season 0 中的真实 `season_number` 和 `episode_number`。TMDB 数据可能缺失、标题语言不一致或特别篇排序与本地文件不同，因此任何匹配都必须先形成可审核计划。

## Goals / Non-Goals

**Goals:**

- 交付单文件 `.user.js` 产物，在 Tampermonkey 中安装后可直接使用。
- 将文件名解析、TMDB 通信、整批匹配、重命名计划与光鸭 API 执行分层，使核心算法可独立测试。
- 允许干扰文字未知；解析器提取多个语义信号，不依赖对每种完整名称写死规则。
- 使用 TMDB 真实数据决定最终 `SxxExx`，特别内容进入 S00 候选但不自行虚构集号。
- 在任何写操作前提供预览、冲突检查和明确确认，并逐项报告结果。

**Non-Goals:**

- 不自动向 TMDB 新增或修改剧集数据。
- 不提供光鸭账号登录，不保存账号密码，不尝试绕过鉴权。
- 第一版不处理电影命名、字幕与视频成对移动、跨目录媒体整理或 TMDB 数据编辑。
- 不对未在 TMDB 中收录的文件自动分配“看起来合理”的集号。

## Decisions

### 1. 使用模块化源码和单文件构建产物

源码按 `parser`、`matcher`、`tmdb-client`、`guangya-client`、`plan` 和 `ui` 分层，通过轻量构建步骤生成单个 `.user.js`。解析和匹配保持为无 DOM、无网络副作用的纯函数，使用 Node 内置测试执行器覆盖真实命名样本。

备选方案是直接维护一个超大 IIFE。它的发布最简单，但难以单元测试和维护，不适合本项目的匹配复杂度。

### 2. 文件名解析采用“归一化 + 跨位置特征提取”

解析过程执行 Unicode NFKC 归一化，区分主名与扩展名，将常见分隔符视为边界，然后独立提取：日期、标准 `SxxExx`、“第 N 期/集”、中文数字、上/中/下或 Part、特别篇语义、发布/编码标签和剩余标题 token。解析结果保留原文、命中位置和警告，未识别文字不盲目删除。

备选方案是一个大正则或完整名称映射表。这会把日期或分辨率误认成集号，也无法在新干扰字符出现时稳定降级。

### 3. TMDB 是集号权威源，且剧集选择必须显式确认

油猴配置使用 `GM_setValue` 保存用户的 TMDB Read Access Token，使用 `GM_xmlhttpRequest` 和 `@connect api.themoviedb.org` 发起请求。先以目录剧名及可选年份调用 `/3/search/tv`，向用户展示名称、原名、首播年、地区和海报；用户选择后缓存 `series_id`。然后请求 `/3/tv/{id}/season/{season}` 和 `/season/0`，以 `zh-CN` 为首选语言，必要时补充原始/英文标题用于匹配。

不会仅因第一个搜索结果热度最高就自动选定，因为同名剧集会导致整批错改。

### 4. 对整个目录做单调序列匹配

每个本地文件与每个 TMDB episode 产生匹配分数，信号包括：

- 已有的明确 `SxxExx`。
- 标题 token 相似度和特别篇类别。
- 文件名日期与 `air_date`。
- 期号、上/中/下、Part 等语义顺序。
- 文件在同目录的自然顺序。

随后用动态规划进行保序对齐，允许跳过本地文件或 TMDB episode。这样当中间缺一个文件时，后续文件不会被压缩到错误集号。正季与 S00 分别对齐，“先导/花絮/加更/特辑”只是 S00 分类信号，不直接决定 episode number。

输出分为高、中、低置信度及未匹配。只有高置信度项默认勾选；任何多对一、一对多、目标同名或 TMDB 缺失均转为显式警告。

### 5. 命名计划是写操作的唯一输入

匹配器不直接调用云盘 API，而是生成包含 `fileId`、原名、目标名、TMDB episode id、分数、依据、警告和选中状态的计划。默认格式为：

`{seriesTitle}.S{season:2}E{episode:2}.{episodeTitle}.{extension}`

并可切换为不含集标题的简洁模式。文件名生成后统一清理路径保留字符、尾部点/空格与连续分隔符，但保留原扩展名。

用户必须在预览表中确认具体项，可修改目标季/集或取消选中；执行按钮再次显示数量和风险确认。

### 6. 光鸭集成使用页面上下文适配器

用户脚本在 `document-start` 安装窄范围的 fetch/XHR 观察器，只记录指向 `api.guangyapan.com` 的必要鉴权头、设备头、列表请求上下文和重命名请求结构。敏感值仅保存在内存，页面刷新后通过新请求重新学习；不写入日志、仓库或持久配置。

列表适配器调用已验证的 `get_file_list`，重命名适配器调用已验证的 `rename`。实现将根据实际捕获样本固定必需字段，对非必需字段保持透传，以降低光鸭前端升级导致失效的风险。如果未捕获授权或请求结构，UI 只显示“等待页面授权/请求上下文”，不允许执行。

备选方案是直接读取特定 localStorage 字段或把 Bearer token 持久化。这两种方式都更脆弱，且扩大凭据泄露面，只能作为明确的手工调试降级，不是默认路径。

### 7. 重命名采用低并发、幂等检查和最终复核

执行前重新获取目录，验证 `fileId + oldName` 仍然一致，并检查所有目标名是否唯一。已是目标名的项视为成功且不重复提交。其余项以默认 2 路并发执行，遇到 401/403 停止整批并要求刷新授权，遇到 429/5xx 进行有上限的指数退避，业务冲突只标记单项失败。

如果一批计划存在名称互换或目标名暂时被本批旧名占用，先将相关项改为带随机后缀的唯一临时名，再进入最终名阶段。每个成功记录原名和新名，为本次会话提供可逆的恢复计划。全部完成后再次读取目录，以服务端结果为准标记验证成功或不一致。

## Risks / Trade-offs

- [光鸭是未公开且可变的内部 API] → 将所有请求细节集中在适配器，从页面请求学习鉴权/设备上下文，并对响应做结构校验。
- [TMDB 数据缺失或错误] → 展示条目链接和匹配依据，允许手工改集号，不为未收录项虚构标准编号。
- [文件名只有顺序信息，与 TMDB 标题不相似] → 使用整批单调对齐，将结果降为中置信度并要求确认。
- [TMDB token 在浏览器本地可被用户脚本读取] → 使用 Tampermonkey 隔离存储，不注入页面 DOM、日志或 URL，并建议使用只读 TMDB token。
- [批量写操作可部分成功] → 逐项状态、有界重试、最终重读和会话内恢复计划；不宣称整批原子性。
- [用户同时在其他页面改名] → 写入前对 `fileId + oldName` 做乐观校验，发现变化就阻止该项。
- [跨域请求受 CSP/CORS 影响] → TMDB 使用 `GM_xmlhttpRequest`；光鸭 API 由用户脚本适配器带已捕获授权请求，并在真实 Tampermonkey 环境做端到端验证。

## Migration Plan

1. 建立模块化源码、构建脚本和测试夹具。
2. 先以只读模式发布：只读取目录、请求 TMDB 并生成预览。
3. 在隔离的测试文件上验证单文件改名和恢复，再启用批量执行。
4. 对用户提供 `.user.js` 更新；回滚脚本版本只停止后续操作，已改名文件通过会话恢复计划单独处理。

## Open Questions

- 光鸭 `rename` 请求的最小必需 body 和设备头需在实现前从已捕获的真实请求中固化为契约测试，不能仅根据前端字符串推测。
- 默认文件名是否包含 TMDB 集标题可在首次真实预览后调整；设计上同时保留完整和简洁模式。
