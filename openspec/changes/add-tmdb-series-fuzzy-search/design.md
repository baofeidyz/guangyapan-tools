## Context

预览表格当前为每个文件渲染一个包含全部剧集的原生 `<select>`，`change` 事件再通过 `season:episode` 值更新重命名计划。该方式可靠但只能依赖滚动或浏览器有限的首字母跳转，在一季包含大量正片和 S00 特别篇时定位成本很高。

功能运行在油猴脚本中，不能假设页面已加载某个 UI 框架，也不应为一个轻量选择控件增加第三方依赖。搜索只针对已从 TMDB 载入内存的剧集列表，不需要新增网络请求。

## Goals / Non-Goals

**Goals:**

- 在每一行提供可输入、可展开、可键盘操作的剧集选择器。
- 按标准季集编号、纯数字集数、中文标题和备用英文标题进行大小写不敏感的模糊过滤。
- 选择和清除后继续复用现有 `assignEpisode`、计划校验和重新渲染流程。
- 保证当前选中集在重新渲染后仍显示准确，不接受无法映射到已加载剧集的自由文本。

**Non-Goals:**

- 不改变自动匹配评分或 TMDB 数据获取逻辑。
- 不实现拼音转换、编辑距离纠错或服务端搜索。
- 不改变重命名计划、缓存或 API 数据结构。

## Decisions

### 1. 使用仓库内实现的组合框，而不是原生 `datalist` 或第三方组件

每行渲染文本输入框、当前选中值和一个按需显示的候选列表，由面板现有的事件委托统一处理 `input`、`focus`、键盘和点击事件。候选项保存规范化的 `season:episode` 键；真正更新计划时仍把该键解析后交给 `assignEpisode`。

原生 `datalist` 的过滤规则和下拉展示在不同浏览器中不一致，并允许留下未映射的自由文本。引入 Select2 等组件则会扩大 userscript 体积并带来宿主页面样式冲突，因此不采用。

### 2. 搜索索引由剧集元数据即时派生

为每个剧集生成显示标签（如 `S03E12 标题`）和规范化搜索文本，索引包含：

- `S03E12`、`S3E12`、`3:12` 等季集编号表达；
- 集数的十进制文本；
- `name` 与 `alternateNames` 中的标题。

规范化会转为小写并移除空白和常见分隔符。查询按分词后的包含关系过滤，所有查询片段均命中才保留；因此支持部分编号和部分标题，但不宣称支持错别字纠正。空查询展示全部候选。

### 3. “不匹配”是一个明确的可选候选

候选列表顶部始终提供“不匹配”。选择它会以空键调用现有清除逻辑；输入被清空但尚未明确选择时，不立即改变计划，避免用户仅编辑搜索词就意外丢失已分配集数。

### 4. 键盘与鼠标共用同一选择路径

输入时更新过滤结果；上下方向键移动高亮项，Enter 确认，Escape 关闭，鼠标点击候选也走相同的提交函数。失焦仅关闭列表，不提交自由文本。列表和输入使用 combobox/listbox ARIA 属性，确保状态可识别。

### 5. 搜索状态保留在 DOM，不进入应用状态

搜索词、高亮索引和展开状态只属于一次选择交互，不写入全局 `state`。确认选择后现有 `update` 会重新渲染面板，并从计划中的 `episode` 恢复显示值。这样避免在每行计划对象中加入临时 UI 字段，也不影响执行和持久化。

## Risks / Trade-offs

- [每行渲染全部候选可能增加 DOM 数量] → 初始只渲染输入和当前值，在展开或输入时生成过滤后的候选，并设置合理的可见结果上限。
- [宿主页面 CSS 可能影响浮层定位或层级] → 所有类名继续使用 `gtr-` 前缀，候选列表定位在单元格内并设置明确的背景、边框和 `z-index`。
- [“模糊搜索”可能被理解为错别字容错] → 当前定义为规范化后的部分匹配；保留实现边界，未来如需拼音或编辑距离可替换纯函数过滤器。
- [重渲染会丢失正在输入的查询] → 只有确认选择或其他计划变更才触发重渲染；选择完成后恢复规范的选中标签属于预期行为。

## Migration Plan

1. 增加可独立测试的剧集标签、索引和过滤函数。
2. 替换预览行中的原生下拉框，并增加事件委托与样式。
3. 更新 UI/交互测试，运行完整测试和 userscript 构建。
4. 发布新版 userscript；无需迁移用户数据。回滚时恢复原生 `<select>` 渲染即可，计划与缓存数据不受影响。

## Open Questions

无。首版按规范化部分匹配实现，不加入拼音和错别字纠正。
