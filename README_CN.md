# 光鸭云盘 TMDB 重命名助手

[English](README.md) | **简体中文**

这是一个运行在 `guangyapan.com` 的 Tampermonkey 用户脚本。它读取当前季目录中的文件，结合 TMDB 的真实剧集元数据生成可审核的重命名计划，再通过光鸭网页正在使用的接口安全执行重命名。

例如，在 `脱口秀和Ta的朋友们/S03` 中，`第一期上`、`第一期下` 等文件会结合 TMDB 第三季的标题、播出日期和顺序进行匹配，并生成类似：

```text
脱口秀和Ta的朋友们.S03E01.剧集标题.mp4
脱口秀和Ta的朋友们.S03E02.剧集标题.mp4
```

“先导片”“花絮”“加更”等内容不会用写死的编号猜测，而是进入 TMDB 第 0 季（S00）候选域；缺少标题、日期或显式编号证据时不会自动选中。

## 功能特点

- 通过 TMDB 数据匹配剧名、季、集号、标题和播出日期。
- 支持中文数字、期数、上/中/下、Part、日期和已有 `SxxExx` 等多种文件名格式。
- 保留 `2160p`、`1080p`、`720p`、H.265/HEVC、H.264/AVC 和 AV1 等版本标签。
- 所有更名先生成预览；中低置信度默认不选中，冲突会阻止执行。
- 提供可搜索的人工剧集选择器、执行后校验，以及当前会话内的反向恢复。
- 光鸭授权上下文只保存在内存中；TMDB Token 只保存在用户脚本隔离存储中。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 或兼容的用户脚本管理器。
2. 打开[最新版本用户脚本](https://github.com/baofeidyz/guangyapan-tools/releases/latest/download/guangya-tmdb-renamer.user.js)并确认安装。
3. 打开光鸭云盘文件页面，右下角会出现“TMDB 重命名”按钮。

也可以克隆仓库后执行 `npm run build`，再安装 `dist/guangya-tmdb-renamer.user.js`。

## TMDB 设置

在 [TMDB API 设置](https://www.themoviedb.org/settings/api)申请 Read Access Token（v4 auth），然后在脚本面板中保存。Token 不会写入网页、构建产物或日志。

当前目录建议采用 `剧名/S03` 结构。脚本会从 URL 识别目录 ID，从 `S03` 识别季号，并要求用户明确选择一次 TMDB 搜索结果；不会仅凭搜索第一项自动确定剧集。

## 使用流程

1. 进入需要处理的 `Sxx` 目录。若面板显示“等待页面请求”，在光鸭页面中刷新一次文件列表，让脚本捕获当前会话的必要请求上下文。
2. 在光鸭列表中选中目标文件夹。脚本优先用该文件夹名称搜索 TMDB；若页面没有选中项，则使用当前目录推导出的剧名。随后明确选择 TMDB 剧集。
3. 检查每一行的目标名称、置信度、匹配依据和警告。可在剧集选择框中输入 `S03E12`、集数或中英文标题片段进行模糊搜索，再人工指定剧集或选择“不匹配”。选择框支持方向键、Enter 和 Escape。
4. 选择完整命名（含 TMDB 集名）或精简命名，并解决所有阻断冲突。
5. 点击执行，再确认数量与警告。执行后脚本重新读取目录，按文件 ID 校验服务端最终状态。
6. 若批次部分成功，可使用本次会话内的反向恢复操作。

## 识别与安全策略

- 文件名会先进行 Unicode 和分隔符归一化；解析规则不依赖某一个固定前缀或后缀。
- 清晰度和视频编码优先从文件名读取，缺失时通过光鸭只读文件详情接口补充；不会仅凭文件大小猜测。
- 同一个 TMDB 集号允许存在多个文件，但每个版本必须具有唯一的清晰度/编码组合；无法可靠区分时会阻止执行。
- 普通季与 S00 分开匹配。特殊内容只有获得 TMDB 元数据证据后才能高置信匹配。
- 已符合 `SxxExx` 的文件默认跳过。重复目标、名称占用、源名称过期或非法名称均会阻止执行。
- 名称互换或循环会先改为唯一临时名。重命名默认最多并发 2 个请求；429/5xx 有限重试，401/403 会停止尚未调度的项目。
- 执行前后都会重新读取文件列表。API 返回成功但最终名称不符会显示为状态不一致。

## 光鸭接口兼容性

光鸭没有为本项目提供稳定的公开 API 合约。脚本在 `document-start` 仅观察光鸭官方页面发往 `api.guangyapan.com` 的文件列表和重命名请求，白名单提取必要请求头与请求体形状，并仅在内存中保存授权上下文。不会持久化光鸭凭据。

当前观测到的主要接口为：

- `POST /userres/v1/file/get_file_list`
- `POST /userres/v1/file/get_file_detail`
- `POST /userres/v1/file/rename`

同时兼容旧路径 `/nd.bizuserres.s/v1/file/...`。光鸭内部接口若改版，适配可能失效；请先用少量、可恢复文件验证。详细的脱敏契约见 [docs/guangya-api-contract.md](docs/guangya-api-contract.md)。

## 本地开发

需要 Node.js 20 或更高版本。项目没有第三方运行时依赖。

```bash
npm test
npm run build
npm run check
```

测试不会调用真实 TMDB 或光鸭账户。真实页面验证应使用独立的测试文件，并在结束后恢复原名称。

## 自动构建与发布

GitHub Actions 会在推送和 Pull Request 时运行测试、构建脚本，并保存构建产物。发布新版本时：

1. 同步更新 `package.json` 与 `src/userscript.meta.txt` 中的版本号。
2. 创建并推送同版本标签，例如：

   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```

工作流会校验标签与源码版本一致，随后创建 GitHub Release，并附加可直接安装的 `guangya-tmdb-renamer.user.js`。
